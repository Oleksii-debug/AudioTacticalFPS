# Extraction runtime identity candidate

This is the extraction-side API for CARR-10; it does not edit or replace the ingestion journal. PR31 at 41b48b18e93f855fd81ccd1c120a4288db91b844 records adapter=page_ocr-v1, config and two package versions, but not actual adapter bytes or Tesseract executable/model identity. A resumed job can therefore mix extraction implementations. Proposed integration: use runtime_identity(Config(...)) in the canonical PDF plan, compare current identity against the stored identity before resume and after extraction before each checkpoint, reject/restart old plans without the field, never overwrite old revisions. Handle IdentityError as an explicit private job failure. CARR-10 owns integration and performance/cancellation policy. Missing engine is explicitly different from a present engine. The function is intended for a trusted local installed environment, not an adversarial runtime.

Reuses Tesseract native --version and --list-langs APIs and existing pinned_tessdata.stage_pinned_models, no new parser, no model download or new dependency.
