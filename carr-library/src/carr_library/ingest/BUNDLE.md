## Operation and limits
Call create_revision_bundle(storage, new_directory, include_all_workspaces=True), retain the returned manifest SHA256 separately in a trusted location, then restore_revision_bundle(new_directory, fresh_database_path, expected_manifest_sha256=retained_digest). The snapshot includes ALL workspaces in the revision database; explicit consent is required. This does not supply per-workspace export, original assets, catalog, notes, evidence, or job-journal backups. Manifest contains version, kind, schema_version, size_bytes, sha256 only. No network, sharing, or private data in repository. Bundle creation uses private staging, exclusive directory creation and no-replace hard links; manifest is published last. Incomplete destination directory after interruption is intentionally not removed or overwritten. Reader requires exact two-file namespace, bounded manifest, independently retained checksum, no duplicate keys and a fresh path outside the bundle; existing restore validates schema and index. Stable private local parents and no concurrent external writers required. No hostile directory sandbox or authenticated archive claim. Size cap applies to publication, not SQLite temporary disk consumption. Windows ACLs, power-loss durability/directory fsync and filesystems without hard links are not accepted yet.
