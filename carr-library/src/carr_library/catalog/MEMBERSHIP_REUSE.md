# Catalog membership candidate (CARR-02)

This service composes the explicit Work/Edition identity model and collection membership from PR #17's bootstrap/universal_library.py (head 4c2ee5ba43a778a2b160325cfe48678eeab213d3) with native SQLite composite foreign keys, unique constraints, savepoints and parameterized SQL. No ORM, alternative database engine or custom search index. SQLite 3.46.1 (public-domain core) exercised through CPython 3.13.5 sqlite3. Existing intake PR #20 (8ef0e769990ac168001cbe028dc63978b6d9e161) supplies the manifest shape; the service does not itself attest manifest origin. Existing storage PR #21 (8a7ed6bbdc84a4c626af2f7a9d54dfe3431a8d0f) accepts caller-owned workspace/edition IDs and asset SHA256, but production integration is NOT_RUN. PR #49 (24d21248b809b8da95d0a13595755a922e8a7aed) uses the same proposed workspace(id) parent. CARR-01/05 must agree on the authoritative schema, IDs, revision FK, transaction boundary and migration before activation. The SQL under tests/catalog is a fixture only, not a migration.

Cairnsearch MIT upstream https://github.com/smwaqas89/cairnsearch/tree/eb5bf13605343e75e3aaf6ce0d8d2ecef8748d93 : re-read PR17 manifest and compared all eight vendored blob IDs with upstream: 8/8 equal. No duplicated extractor. Zoteus https://github.com/oscardvs/zoteus and official Zotero local API https://www.zotero.org/support/dev/web_api/v3/local_api are useful optional interoperability paths, not a drop-in local catalog (Zoteus may fall back to cloud; live Zotero not required for general release). Existing RIS preview PR44 is the offline interchange candidate; no additional service or network dependency introduced in this package.

Scope: manifest row deduplication (not physical byte-store deduplication), explicit work/edition identity, ordered author names, unknown metadata, multiple collection memberships, archive preserves membership, fail-closed destructive edition/asset deletion, isolation through scoped service and composite FKs, rollback on duplicate edition registration. Caller must authorize the workspace, own the transaction (BEGIN IMMEDIATE), and supply trusted verified intake manifests. This is not a security boundary against a caller with arbitrary SQLite access. No rights verification or actual citation/byte-store persistence, no catalog-wide CRUD/metadata edits, idempotent registration retries, full author identity normalization, integration with RIS/extraction, migration/backup, Windows/NVDA or independent acceptance claimed. Do not auto-execute test schema against production. U1/U3 remain open. Next: agree schema and integrate actual intake + storage transaction and revision linkage with CARR-05/01.
