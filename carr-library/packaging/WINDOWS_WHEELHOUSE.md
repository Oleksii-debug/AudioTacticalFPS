# Windows x64 / CPython 3.11 wheelhouse preflight (candidate)

Reuse upstream uv 0.10.0 (MIT/Apache-2.0, https://github.com/astral-sh/uv/tree/0ba432459aa4e84d793fd8cfc98d13cf619316bb) from PR #35 and packaging 25.0 (Apache-2.0/BSD-2-Clause, https://github.com/pypa/packaging/tree/f58537628042c7f29780b9d33f31597e7fc9d664) for PEP 508 root requirement parsing. Build tools only, not new application dependencies. Use reviewed, already available binaries; no automatic download or source build.

From carr-library, `python packaging/windows_wheelhouse.py approved-roots.in approved-wheelhouse windows.lock --approved-manifest approved.json` resolves a hash-pinned Windows x64 / CPython 3.11 target using uv's existing resolver and hash-mode dry run. Supply one exact named version per line in the root requirements and a directory of approved wheels, with upstream provenance and hashes reviewed separately. The required external approval JSON is a nonempty object mapping each exact wheel filename to its independently approved lowercase 64-character SHA256. Include every wheel and no other files. Do not generate the approval from the same untrusted staging directory. The manifest and output must be outside the wheelhouse. Native packaging.parse_wheel_filename validates names and uv resolves dependencies; the wrapper checks inventory and hashes before invoking uv, checks generated hashes against the approval and rechecks staging bytes before publishing. Run in a network-disabled environment for stronger isolation. Do not use untrusted inputs or mutable wheelhouses; uv offline flags do not replace OS isolation, and hashes generated from local wheels are not independent proof of upstream authenticity. No source distribution builds or interpreter downloads. The output is a target resolution candidate, not an installer or a security approval. Existing locks are preserved.
