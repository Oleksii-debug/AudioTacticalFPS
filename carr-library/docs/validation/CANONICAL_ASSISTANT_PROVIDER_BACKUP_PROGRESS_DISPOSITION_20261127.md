## Concrete gaps found and reconciled

### Provider output and settings recovery

The initial current gateway lacked complete raw/decoded credential-echo
protection for all selected providers. The reconciled current providers.py
checks returned bytes and recursively checks decoded JSON/text, including HTML
character references, before publishing a completed ledger receipt. LLM JSON
uses the existing duplicate-key rejection hook so an escaped secret cannot hide
in a discarded duplicate property. Google wire JSON is checked before typed
translation decoding can discard metadata; accepted decoded translation still
has its independent ledger digest. A request that may have been sent remains
uncertain on failure and is not automatically retried.

Current profile import validates the whole selected export before a write,
refuses unknown/secret fields and identity collisions, and clears credential
references. It creates no provider request or saved execution approval.
provider_recovery captures bounded nonsecret current profile metadata and
read-only usage history with source hashes and a final unchanged-source check.
Complete backup restores those records as passive data. The API settings UI
offers explicit recovery preview/import and read-only history export through
the existing destination publisher. It does not reactivate an old ledger or
borrow a former vault reference.

Regression owners include tests/e2e/test_provider_credential_echo.py,
test_provider_profile_import.py, test_provider_ledger_lifetime.py,
test_provider_transport_boundaries.py, test_provider_transport_contract.py,
the Google gateway suites, and tests/storage/test_provider_recovery.py.
The relevant new population is 27 echo + 30 import + 39 passive recovery cases;
actual qualification must be read from the exact executing head's evidence.

Exports use the current verified evidence renderer and retain exact quotations,
source origins and separate notes. They require the currently approved output

Committed completion survives late cancellation and owned cleanup warnings.
The ordinary publisher's callers retain their default behavior, and the
canonical PR191 pre-read identity refusal remains present.

Current named workflows save only allowlisted typed steps as inert drafts.
Combining drafts rebases each draft's local topic references. Loading clears

Existing CLI, planner and native assistant expose the feature through the same
service.

### Backup compatibility and preservation

The current backup still asks actual producers for typed state. Optional roots
are absent only on FileNotFoundError; inaccessible existing roots, walk failures,
links and unknown committed entries cause visible refusal. Current templates,
audio batches, retained playback queues, reading appearance/publication state,
translation scopes and provider recovery remain in that inventory.

Historical state adapters use exact original manifest envelopes and retain the
original manifest bytes beneath a hash-addressed passive archive. The generic
historical 32 GiB limit and 4096-character/2048-component path compatibility are
kept separate from current typed producers' narrower paths. A generic historical
blob is not thereby validated as a current executable job.

PR196 is a real policy correction: omitted/false generated_audio_included may
not accompany the exact canonical worker or worker-history cache layouts.
Current typed ASR producers continue their own cache exclusion. Historical
transcription input accounting separately permits its existing 32 GiB per
source/64 GiB input aggregate and bounded metadata while retaining the outer
archive/caller limit and the generic-state bound. Those larger declarations
do not change the current new-execution job limit or constitute a 64 GiB
throughput measurement.

Coverage includes tests/storage/test_legacy_state_portability.py,

test_historical_asr_cache_policy.py, current typed producer backup suites, and

## Explicit compatibility and release limits

* Old canonical provider-export and assistant-job JSON are not silently treated
  as the current schemas. Supported historical manifests preserve their original
  data; current import/review creates fresh disconnected settings or plans.
  Raw preservation is distinct from automatic migration or resumed authority.
* A canonical default voice attached to an old provider profile does not become
  current remote permission. Current TTS uses an explicit request voice; current
  profile recovery/import requires current reconnect/review.
* Stored external original/model paths remain provenance, not instructions to
  open, download, execute, or transmit those paths after restoration.
* The source audit does not qualify a model corpus, a 135-language promise,
  hardware playback/recording, NVDA, an authenticated production publisher,
  Authenticode, or full-size ASR throughput.
* A source-only successful review and a declared test Counter are not runtime
  evidence. Frozen failed attempts remain failed. In particular the earlier
  template ff6 attempt is still 504 passed + 1 failed + 1 skipped per 506-case
  lane, with an unqualified native timeout; the corrected 3366 attempt has its
  own immutable run identity.
