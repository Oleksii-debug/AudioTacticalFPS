## Finding and reuse-first decision

PR25's search_active currently constructs full contiguous page spans. Its separate hybrid API accepts caller-supplied spans and an already relevance-filtered local ranker; it does not promise to split long pages. That is a missing production handoff, not an assertion of a shipped bug. FastEmbed Apache-2.0 at https://github.com/qdrant/fastembed/tree/2099c36036115e689ea9b3b5bf1aafa79dc01190 advertises 128-token truncation for the pinned multilingual MiniLM in pooled_embedding.py. Its common/preprocessor_utils.py (blob 1da0d629a637c0b71924eca1a92edce2f311c52f) enables truncation, and text/onnx_text_model.py _token_count sums attention masks of already encoded (potentially truncated) inputs. Do not use that count as proof that original input fits. No live tokenizer or inference executed in this run.

Prefer the already-required Hugging Face tokenizers dependency, using a separate local tokenizer from the verified bundle, with truncation and padding disabled for measuring original input and source character offsets. Reuse its existing Encoding offsets / overflow APIs, not a new tokenization engine. Actual pinned API and offset behavior on this model must pass tests before adopting. No additional NLTK dependency proposed: independently evaluated installed NLTK 3.9.2 (Apache-2.0) at https://github.com/nltk/nltk/tree/4e17ea390c526ec9cb9e5ef5eb3733ac118dbb8d; upstream nltk/tokenize/punkt.py blob 877b79dd29103464d13c967cc74e030a92c7cfbc matches installed bytes. Punkt span_tokenize retains exact offsets for four synthetic EN/UK/SK/mixed Unicode cases with a tiny fixture abbreviation profile; but long sentence and unsegmented CJK cases show it is not a universal model-budget boundary. No language model training and no copying NLTK source.

## Acceptance for CARR-07 with CARR-04/05/11/13

1. Authorize workspace/collection/topic and active edition/asset/revision in one consistent snapshot before constructing any semantic windows. No text from other scopes sent to model.
2. Use token-budgeted, bounded contiguous windows within one source locator; count special tokens and any model-specific prefixes. Never rely on truncated count, word count or character count as the real limit. Re-encode each exact raw slice without truncation and verify it fits. Handle overlong queries explicitly, without silent truncation. Validate offset units (Unicode code points vs bytes) and Unicode normalization mapping on pinned runtime; reject malformed spans.
3. Maintain exact source key, page or logical locator, revision, full-page digest and [start,end) code-point span; every returned quote equals raw[start:end]. Do not join noncontiguous spans or invent printed labels. Window IDs are stable and versioned. Preserve raw source and authorize historical evidence separately.
4. Ensure coverage of relevant tail text on long pages and long single sentences; do not silently omit CJK, RTL, combining marks, OCR whitespace or punctuation. Reject unsupported/over-budget candidates or visibly degrade to lexical-only search, never report full semantic coverage. Use bounded overlap, deduplicate repeated windows from same source before final ranking and retain existing RRF and BM25 rather than rewriting either.
5. Actual offline pinned model benchmark: late-page target, long single sentence, multilingual same-title/different workspace, misleading overlap, no evidence and truncated-count regression; compare lexical/semantic/hybrid recall and MRR, record inference time/RAM, citation fidelity and explicit NOT_RUN for absent model. Test a relevant late-page result separately from an early identical distractor. Keep held-out queries independent. No generated quotes. No production rollout until exact runtime and independent review.
