## Required shared identity and transaction

- One SQLite database and authoritative workspace(id TEXT) as parent. Work and edition identities are composite (workspace,id); globally unique revision id plus workspace/edition binding remains in existing Storage. Asset identity is SHA256; distinct editions may share bytes. Never infer identity from title/author. Keep catalog_edition asset immutable and do not retarget historical revision/quote. One matching parent UNIQUE(workspace,id,asset) and child immediate non-null FOREIGN KEY(workspace,edition,asset) REFERENCES catalog_edition(workspace,id,asset) on revision. Preserve existing sealed/page/active/indexed/FTS constraints and immutable triggers. No REPLACE or cascading destructive deletion. Use SQLite's native FK and transaction APIs rather than custom validators for this boundary.
- Every writable connection enables and verifies foreign_keys and recursive_triggers before BEGIN. Storage owns BEGIN IMMEDIATE for a whole publication unit; CARR-10 registers catalog/collections and stages all revisions using the same connection inside this unit. No nested BEGIN, no inner commit. Standalone publish_revision remains a wrapper around Storage.transaction and stage_revision. Explicit stage_revision requires active caller transaction, uses native SAVEPOINT and the existing publication body unchanged; statement error rolls back stage and propagates, engine-level ROLLBACK can end outer transaction so do not mask original error. On any import failure CARR-10 rolls back entire unit, not just last stage. File staging/reconciliation outside SQL remains CARR-10/13 responsibility. Do not expose partial import as success.
- Existing version 1 is only a candidate, not universal database format. CARR-05 must deliver a versioned combined schema and validate version/schema identity at open. Fresh installation creates catalog and revision tables transactionally; existing candidate database upgrade must use private backup/staging, verify historical mapping and all dependencies, reject missing/mismatched binding without guessing and preserve source, not run ad hoc executescript on a live library. Rebuild/validate FTS. Include existing QA-007, REL-003 topic reachability and saved evidence checks from PR54 before snapshot publication; PR54 full evidence verification not covered by this probe. Migrations, immutable source bytes, catalog metadata attestation, topic/evidence and workspace CRUD are not solved by this narrow contract.
- Scope enforcement at reads still mandatory. Composite FK is integrity, not access control. Archived evidence remains anchored to historical revision; active FTS only active source. Normalized/semantic indexes are derived and must publish atomically or fail closed until rebuilt. Require independent Windows and CI evidence.
