# Підключення до спільного реєстру читача і студії

> Цей опис збережено як історію контракту. У поточній інтеграції зміни реєстру
> вже застосовані; інструкція користувача — `DORDIAI_DESKTOP.md`. Повторно
> застосовувати наведений нижче патч не потрібно.

`integrations/dordiai_speech.py` містить тільки споживача готового
`DordiaiVoicesAdapter`. Другого процесного протоколу або акустичного рушія
немає. Залежність — спільні `speech.runtime` та `speech._io`; сторонні
Python-залежності не додаються.

## Мінімальні спільні зміни

`docs/contracts/DORDIAI_SPEECH_REGISTRY.patch` містить два точні доповнення:

1. `VoiceRegistry.discover(..., dordiai=None)` після звичайного пошуку
   викликає `install_dordiai_provider(registry, dordiai)` для явно заданої
   конфігурації.
2. `VoiceRegistry.fingerprint(voice_id)` включає результат необов'язкового
   `provider.fingerprint(voice_id)`. Це потрібно застосувати перед використанням
   кешу: одного відбитка інтерпретатора недостатньо для зміненого голосу.

Патч підготовлено проти справжнього паралельного `speech/runtime.py`:
SHA-256 `f8e592afde25927b50d37c9c089730e5a2917aefe831f997650cff2d96440b98`.
Відбиток після цих двох змін:
`c95afc9b04abad65d457ae6eafb39e2bc284ebed38185aeb1a6289f1c35cbdfe`.
Використаний без змін `_io.py`:
`4eaa2259cf5e31ac7a1f5155da62761bb374d258aa37c51227f23c3e3da7ebca`.
Спільні файли іншого працівника в цьому коміті не перезаписуються.

З кореня репозиторію після інтеграції спільного speech-пакета:

```text
git apply --check carr-library/docs/contracts/DORDIAI_SPEECH_REGISTRY.patch
git apply carr-library/docs/contracts/DORDIAI_SPEECH_REGISTRY.patch
```

Уже відомий реєстр можна доповнити без зміни discovery:

```python
from carr_library.integrations.dordiai_speech import install_dordiai_provider

provider = install_dordiai_provider(registry, {
    "enabled": True,
    "runtime_directory": selected_installed_kx47_runtime,
})
```

Немає конфігурації або `enabled=False` — немає перевірки приватних шляхів,
імпорту ресурсів чи запуску процесу. Наявна конфігурація — явний локальний
вибір. У продукті зберігаються лише шлях, прапорець і, за потреби, перевірений
відбиток `expected_worker_sha256`; стандартний відбиток уже міститься в
адаптері. `python_executable` є необов'язковою експертною настройкою для
окремо підготовленого оточення.

## Передача в наявний інтерфейс налаштувань

Поточні `runtime_settings.py` та `ui/engine_settings.py` використовують
строгу схему збережених локальних рушіїв. Інтегратор додає необов'язкове
поле `dordiai` з початковим значенням `None`; старі документи схеми 1
нормалізує через `setdefault('dordiai', None)` перед перевіркою множини
допустимих ключів. Поле додається до дозволених ключів читання/збереження
і до скидання налаштувань.

Після цього `runtime_settings.voice_registry` передає
`VoiceRegistry.discover(dordiai=value['dordiai'])`. Наявні Piper, SAPI,
eSpeak і Flite реєструються як раніше.

У наявному діалозі локальних рушіїв достатньо окремої кнопки
«Підключити встановлений dordiai-voices», доступного клавіатурою вибору
каталогу `kx47Runtime`, прапорця ввімкнення та текстового результату
перевірки. Типовий add-on має назву каталогу `kx47Voices`, а продукт —
dordiai-voices. Перевірку й первинне хешування великого встановлення
виконувати фоновим працівником. Показувати кількість фактично готових
поєднань голос/мова, `registry.notices` і відсутні/часткові ресурси через
`provider.adapter.language_statuses()`. Нуль доступних поєднань не видавати
за успішне акустичне приймання.

Після зміни конфігурації або закриття власника читача/студії потрібно
викликати `provider.close()`; кнопка скасування може викликати
`provider.cancel()`. Жодних завантажень або мережевої служби цей потік
налаштувань не запускає.

## Поведінка споживача

Кожна структурно сумісна комбінація профілю та мови стає окремим `Voice`.
Її ідентифікатор стабільний і не підмінює непідтверджені регіональні
варіанти. Оголошені тільки `rate`, `volume`, `pitch`. Налаштування швидкості
спільного читача переводиться в коефіцієнт `2 ** (rate / 10)`, стандартна
висота dordiai — 50. Озвучення пунктуації й фонеми не оголошуються.

`render` делегує блоки справжньому адаптеру й записує PCM WAV: 24 000 Гц,
моно, 16 біт. Перевіряє формат, кількість байтів, скасування, дедлайн
усього фрагмента та незмінність установлених ресурсів. Використовує
існуючий атомарний `speech._io.new_output`, тому чужий файл не
перезаписується і часткова операція не публікується. Спільний реєстр
далі об'єднує фрагменти своїм звичайним шляхом.

Відбиток для кешу враховує вміст ресурсів `models`, приватного `python`,
модулів/config runtime, маніфесту, мосту CARR, конкретного голосу й мови.
Перший виклик читає встановлені файли; незмінні файли повторно не
хешуються, поки їхні сигнатури не змінилися. Доданий, змінений або
видалений ресурс змінює ідентичність. Назви приватних файлів і їхній
вміст не повертаються з цього API. Відбиток не є доказом якості вимови.
Якщо змінилися базові ресурси без оновлення індексу пакетів, наступний
фрагмент перезапускає прогрітий процес, щоб він завантажив нові дані.

## Перевірка інтеграції

```text
python -m pytest -q tests/integrations/test_dordiai_speech.py
```

До злиття паралельного speech-пакета тестовий запуск може встановити
`CARR_TEST_SPEECH_RUNTIME_SOURCE` на заморожену локальну копію справжніх
`runtime.py` та `_io.py` із наведеним мінімальним патчем. Тести не містять
дубліката цих модулів. Після інтеграції змінна не потрібна.

Перевірено реальні `VoiceRegistry`, `SpeechSettings`, WAV-об'єднання,
атомарне збереження, discovery, відбитки кешу та обробку скасування/лімітів.
Джерело PCM у цих регресіях — позначений синтетичний процесний стенд.
Справжній акустичний синтез Windows і приймання NVDA залишаються окремими
вимогами, описаними в `DORDIAI_VOICES_CONTRACT.md`.
