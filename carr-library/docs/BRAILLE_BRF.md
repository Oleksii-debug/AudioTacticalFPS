# Окремий BRF із збереженого джерела

Цей необов'язковий шлях експорту створює **простий шестикрапковий Braille ASCII файл** із явно обраного діапазону вже імпортованого джерела. Він використовує локально обраний офіційний Liblouis 3.39.0 для Windows x64. Архів runtime, DLL і таблиці не входять до пакета Resonance; застосунок їх не завантажує та не встановлює.

Це обмежена частина V3-20. Програмна перевірка клітинок і збереження файлу не підтверджують тактильну якість мови, правильність сторінкової верстки або придатність для брайлівського принтера. Поточні таблиці: `en-ueb-g1` (English UEB grade-1) і `uk` (українська таблиця Liblouis). Каталог 135 мов не є переліком перевірених BRF-можливостей.

## Обрати runtime

Використовуйте незмінений офіційний [liblouis-3.39.0-win64.zip](https://github.com/liblouis/liblouis/releases/download/v3.39.0/liblouis-3.39.0-win64.zip). Розпаковувати його для Resonance не потрібно. Зберігайте архів як звичайний локальний файл, без символічних посилань, reparse points або додаткових жорстких посилань.

Зафіксована ідентичність:

| Поле | Очікуване значення |
|---|---|
| Реліз | 3.39.0, 1 вересня 2026 року |
| Архітектура | Windows x64 |
| Розмір архіву | 5 762 099 байтів |
| SHA-256 архіву | `64d669ac30f1411e0023b1cecc81c7a7b5374678ee41302c95ac8c7c8fbc6591` |
| Відповідний source commit | `2e775aca674cd2910e272eed7736acceb4c2e4a2` |
| C API | `lou_version() == 3.39.0`, `lou_charSize() == 4` |

Повні ідентичності DLL-архіву, відповідного source archive та 17 файлів із включеними підтаблицями записані в [windows-braille-runtime.lock.json](../packaging/windows-braille-runtime.lock.json). Згаданий у технічному проєкті draft commit `457d5484a631e7c18ad4f57c1256c6496af14dd0` є іншим станом upstream і не підміняє цей реліз.

Перевірка архіву звіряє повний SHA-256 **до** ZIP-розбору. Потім перевіряються точні файли таблиць із відповідного source commit. Інший реліз, змінена таблиця, неповний архів, неправильний формат DLL або невідповідна native-залежність зупиняють операцію. Довільний executable, шлях до таблиці або аргументи командного рядка не приймаються.

## Експорт у вікні бібліотеки

1. Відкрийте потрібну бібліотеку та оберіть одну книгу в **Books and Collections**.
2. У меню **Reading** оберіть **Export selected source as plain BRF...**.
3. Введіть діапазон позицій читання, наприклад `1-3`. Це позиції збереженого джерела, а не обіцянка відтворити друковані номери сторінок.
4. Оберіть одну з двох таблиць, офіційний ZIP runtime та окремий файл із розширенням `.brf` поза приватною бібліотекою.
5. Після фонової перевірки прочитайте назву джерела, діапазон, кількість символів, таблицю, ідентичність runtime та попередження про джерело. Фінальне запитання має **No** за замовчуванням. Лише явне **Yes** запускає перетворення.

Наявний файл потребує окремого явного підтвердження. Підтвердження прив'язане до саме того файлу, який був показаний у запитанні. Якщо файл або маршрут до нього змінився, чи після вибору з'явився новий файл, експорт відмовляється його підміняти.

Зміна бібліотеки, теми, кореня на диску або збереженого джерела скасовує старий вибір. Після відновлення бібліотеки повторно відкрийте цю дію та заново оберіть джерело й файл результату. **Cancel current operation** діє через наявний спільний worker та власника native-процесу. Тимчасові вхідні файли залишаються у власності операції, доки її native-нащадки не завершені.

Оригінал не переписується. BRF є похідним результатом і не надає нових повноважень цитування, підтвердження OCR або права виконувати збережену операцію після restore.

## Командний рядок

Запускайте ці команди через Python **встановленого та перевіреного** Resonance. Позначення `<installed-python>` потрібно замінити фактичним шляхом цього runtime; це не пропозиція встановити сторонній Python.

Перевірка локального архіву без завантаження DLL:

```text
<installed-python> -I -B -m carr_library braille inspect --runtime-archive "C:\\Local runtimes\\liblouis-3.39.0-win64.zip"
```

Експорт у **новий** файл:

```text
<installed-python> -I -B -m carr_library braille export --root "C:\\My library" --workspace WORKSPACE_ID --edition EDITION_ID --first 1 --last 3 --table uk --runtime-archive "C:\\Local runtimes\\liblouis-3.39.0-win64.zip" --output "C:\\Exports\\selected-source.brf"
```

Ідентифікатори беруться з вашої поточної бібліотеки; приклади не створюють нової бібліотеки. Необов'язкові `--topic` і `--revision` обмежують вибір існуючою темою та ревізією. Командний рядок не має неявного overwrite або прапорця обходу підтвердження: оберіть нове ім'я, якщо файл уже існує.

Успішний результат містить SHA-256 BRF, ідентичність source range, runtime і таблиці. Якщо фінальний файл уже опублікований, але прибирання його staging залишило повідомлення, результат зберігає це повідомлення; його не слід автоматично повторювати як невдалий експорт.

## Межі простого формату

| Можливість | Межа цього адаптера |
|---|---|
| Текст | 1–100 000 символів, до 4 096 логічних рядків |
| Вихід | До 2 MiB, шестикрапковий Braille ASCII, CRLF між логічними рядками |
| Unicode | Передається C API як чотирибайтові code points; текст `\\x2801` не інтерпретується як escape |
| Непідтримуваний символ | Відмова без публікації замість стандартного undefined-представлення Liblouis |
| Восьмикрапковий результат | Відмова; крапки 7/8 не обрізаються |
| Контрольні символи | Tab, form feed, NUL та інші C0/C1, окрім логічного newline, відхиляються |
| Верстка | Немає ширини рядка, пагінації, заголовків сторінок, змісту чи налаштувань принтера |
| Складне джерело | Зображення, таблиці, нотний запис і структура математичних формул не відтворюються |
| Зворотне перетворення | Не надається |
| Якість | Потрібне окреме тактильне читання та мовне редагування; NVDA й фізичний принтер не кваліфіковані |

Liblouis застосовує правила обраної таблиці до тексту: BRF не є взаємно однозначним кодуванням оригіналу. Підтримувані таблицею орфографічні та форматні правила можуть змінювати кількість клітинок. Перенесення логічних рядків зберігаються, проте це не сторінкова верстка.

Одна операція резервує 1 логічний CPU slot, 512 MiB заявленої пам'яті, до 32 MiB приватного staging і до 2 MiB виходу. Це кооперативний ресурсний бюджет у наявному ResourceBroker, а не вимір фактичної пам'яті DLL чи sandbox для довільного native-коду. Фіксований native worker має 60-секундну межу; він не приймає мережеві адреси, shell-команди або довільні таблиці.

## Перевірка та відтворення

Два звичайні strict-модулі перевіряють контракти з синтетичним runtime, без копіювання upstream DLL або таблиць:

- `tests/reader/test_braille.py`: джерело, SHA/ZIP-границі, незмінність оригіналів, no-clobber, Stop, scope та утримання cleanup owner;
- `tests/ui/test_braille_actions.py`: наявний reader action, відкладена робота, скасування picker/підтвердження та зміна scope.

`scripts/windows_braille_smoke.py` окремо перевіряє фактичний офіційний DLL, обидві таблиці, довгий рядок, literal backslash, відмову для unsupported/8-dot, встановлений CLI і похідний експорт. Він порівнює встановлені Python-модулі з точним checkout до та після виконання й потребує вже локально обраного архіву. Звіти цього probe не є перевіркою native reader menu, ручного NVDA або тактильної якості.

При підготовці цієї зміни source review завершений, а нові тести, DLL та native probe **ще не виконані**. Результат конкретного незмінного CI head має бути записаний окремо перед будь-якою заявою про виконаний runtime. Цей текст не перетворює наявність тесту на успішний результат.
