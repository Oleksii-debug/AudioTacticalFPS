# Оформлений переклад збереженого DOCX

Це окремий спосіб зібрати новий DOCX із уже схвалених завдань перекладу. Він користується тим самим каталогом, збереженим оригіналом, ReadingDesk, профілем перекладача, дозволами, обліком запитів і захищеним експортом, що й звичайний переклад документів. Нового сервера, черги або сховища завдань немає.

## Що підтримує цей профіль

Профіль `carr-docx-body-layout/1` підтримує основні абзаци й прості прямокутні таблиці, які вже приймає канонічний імпорт DOCX. Межі одного документа: 64 MiB архіву, 2 000 000 вихідних символів і 64 непорожні абзаци разом із комірками таблиць. Порожні абзаци залишаються на місці.

У новому архіві змінюється лише `word/document.xml`. Нестосовані частини пакета копіюються з точним збереженням їхніх байтів після розпакування: визначення стилів, зв'язки, придатні медіафайли та інші частини. Структура абзаців, простих таблиць і їхні властивості залишаються. Це не обіцянка однакової верстки після відкриття в Word: переклад має іншу довжину, а Word заново обчислює переноси й сторінки.

Змішане форматування в одному абзаці має явне обмеження: весь переклад отримує формат першого текстового фрагмента. Властивості інших фрагментів зберігаються, але їхній текст стає порожнім. Розподіл жирного, курсиву та інших ознак за окремими перекладеними словами не відновлюється.

Підтримується одне гіперпосилання, яке охоплює весь текст абзацу; його адреса й зв'язок залишаються незмінними. Абзац із кількома посиланнями або звичайним текстом поряд із посиланням відхиляється до схвалення.

Канонічні заборони імпорту залишаються чинними. Зокрема, цей профіль не приймає поля, виноски й кінцеві примітки, відстеження змін, прихований текст, текстові об'єкти чи малюнки в основному тексті, вкладені або об'єднані таблиці. Підписані, макросні та ActiveX-пакети також відхиляються. Текст колонтитулів та інших незмінених частин не перекладається. EPUB і точне відновлення змішаного форматування не входять до цього профілю.

## Робота у вікні

1. Відкрийте потрібну бібліотеку й дослідницьку тему. Оновіть поточну сторінку **Books and Collections**.
2. Відкрийте наявну робочу станцію **Translate retained documents and ranges**, потім кнопку **Translate DOCX with layout**.
3. Натисніть **Choose retained DOCX** та явно виберіть одне з видимих видань. Програма перевірить саме збережений оригінал і його поточну редакцію. На цьому кроці текст не надсилається перекладачеві.
4. Виберіть уже налаштований профіль, мови, за потреби ресурс глосарія Advanced v3 та загальний бюджет. Для локального LibreTranslate бюджет зовнішніх витрат дорівнює 0. **Fetch DOCX languages** потребує окремого підтвердження й не надсилає текст документа.
5. **Preview DOCX translation** показує джерело, точне зіставлення абзаців, обсяг, параметри, бюджет і обмеження форматування. **Approve and save DOCX jobs** має відмову за замовчуванням. Після підтвердження зберігаються звичайні завдання перекладу, по одному на непорожній абзац; запитів до перекладача ще немає.
6. **Run / resume DOCX jobs** запускає лише явно збережені завдання. **Stop after current request** зупиняє подальші запити в межах наявного механізму скасування; уже прийняті квитанції не стираються.
7. Після завершення всіх завдань **Export new translated DOCX** створює новий файл поза приватною бібліотекою. Перезапис існуючого файлу не дозволяється. Якщо запис уже відбувся до пізнього натискання «Стоп», результат відображається як завершений.

Зміна бібліотеки, підміна її каталогу за тим самим шляхом, зміна теми або закриття вікна зупиняє роботу цього вікна й забороняє оновлювати застарілий інтерфейс. Кожна передача тексту зберігає перевірки поточного профілю та первісного дозволу.

## Уже збережені завдання і відновлення

Щоб зібрати файл пізніше, знову виберіть той самий збережений DOCX і натисніть **Choose saved paragraph jobs**. Потрібно явно вибрати рівно одне завдання для кожного абзацу, з однаковими профілем, мовами й глосарієм. Програма перевіряє редакцію, хеш оригіналу, вихідний текст і позиції та впорядковує лише ці вибрані ідентифікатори. Вона не підмінює їх схожими завданнями автоматично.

Завершені завдання можна експортувати без активних облікових даних і після звичайного повного відновлення бібліотеки. Для цього джерело треба відкрити заново у відновленій бібліотеці. Старе захоплення з попереднього каталогу не є дозволом. Нові запити після перенесення або відновлення потребують нового перегляду й підтвердження за чинними правилами TranslationService.

У резервній копії використовуються наявні збережений оригінал, джерельні прив'язки, завдання й квитанції. Нового простору приватного стану для оформленого перекладу немає. Зовнішній експорт не стає оригіналом або джерелом права на цитування.

## CLI

Спочатку налаштуйте профіль через наявний інтерфейс облікових записів; секретів у параметрах команд немає. Значення WORKSPACE, EDITION, PROFILE та ідентифікатори завдань беруться з вашої бібліотеки й результатів команд.

```text
python -B -m carr_library translate --data-dir LIBRARY docx-preview \
  --workspace WORKSPACE --edition EDITION --profile PROFILE \
  --source en --target uk --budget 0

python -B -m carr_library translate --data-dir LIBRARY docx-submit \
  --workspace WORKSPACE --edition EDITION --profile PROFILE \
  --source en --target uk --budget 0 \
  --review-sha256 EXACT_REVIEW_SHA --approve-local

python -B -m carr_library translate --data-dir LIBRARY docx-run \
  --workspace WORKSPACE --edition EDITION JOB_1 JOB_2 JOB_3

python -B -m carr_library translate --data-dir LIBRARY docx-export \
  --workspace WORKSPACE --edition EDITION \
  --output NEW_TRANSLATED.docx JOB_1 JOB_2 JOB_3
```

Для Google замість `--approve-local` застосовується явний `--approve-remote` і ваш погоджений бюджет. Не копіюйте 0 як оцінку вартості платного провайдера. За потреби всі команди мають `--topic`. Preview/submit підтримують чинні `--glossary` і `--rate-per-million`. Ctrl+C використовує вже наявне обмежене скасування. У Windows введіть команду одним рядком або застосуйте правила продовження рядка своєї оболонки.

## Перевірка і межі доказів

Модулі тестів перевіряють реальні DOCX, ізольовані процеси форматування, прив'язку імпортованого модуля, збережені завдання, підміну джерела/призначення, скасування, захищений запис і відновлення. Синтетична відповідь перекладача не є доказом мовної якості або роботи приватної моделі.

Окремий `scripts/windows_translation_layout_smoke.py --source-root SOURCE/src` призначений для встановленого Windows-пакета: він вимагає реальні wx-кнопки, клавіатуру, DesktopExecutor/ProgressHub, встановлені процеси форматування, точні хеші модулів до й після очищення та фактичний DOCX. Вибір файлів, відповіді на підтвердження та транспорт перекладу в цій перевірці контрольовані.

Наявність цих тестів не означає, що вони вже пройшли на поточній збірці. Фактичні результати мають бути прив'язані до точного commit/tree. Відкриття й візуальна перевірка верстки в Word, мовна якість, реальний перекладач і ручна перевірка NVDA залишаються окремими видами приймання.
