## Composition and recovery findings

- One canonical Audio Studio remains based on `audio.models.ProductionPlan`, `audio.production.render_project` and `ui.audio_studio.StudioController`. The live reader reuses the same engine registry and narration model. A second Studio, renderer, assistant or generic state copier was not imported.
- OCR management participates in the main command registry. The keyboard installer runs after module installers. CSL processor, style and locale resources are included together with the bibliography entrypoint; the integrated package declaration retains acquisition, audio and speech.
- A real wheel build exposed that the new speech package was initially absent from explicit setuptools packages. Commit `c6d7be99cf789c47dc1ae61e90e9fb6c78de9de2`, included in the reviewed checkpoint, corrects this. A rebuilt wheel contained all seven byte-identical speech modules; isolated `python -I` imports of the shared speech package and voice-reader UI succeeded from that wheel. This packaging result is not native UI acceptance.
- Live-reader sources bind workspace, edition, sealed revision, exact ordered locations, asset and text digests. Synthesis checks the source and cancellation before publication and before playback. Resume checks both the text/voice/settings identity and actual WAV digest. Historical bindings are not retargeted.
- The V4 backup writer and shared verifier remain `library_backup.py` and `backup_sidecars.py`. Three legacy V3 shapes are discriminated strictly; unexpected files and unavailable producer validators fail visibly. The explicit registry never treats arbitrary JSON or an entire state directory as safe backup content.
