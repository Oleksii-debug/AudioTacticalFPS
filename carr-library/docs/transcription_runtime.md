# Local transcription runtime and recovery

The transcription workstation uses the supplied external worker through its
`--job-dir` file protocol. The public application retains sources, manages the
process, validates recognition checkpoints, produces derived exports, and keeps
durable recovery state. It does not contain another Whisper inference engine.

## Current evidence

The public protocol tests launch a real isolated Python subprocess with a
synthetic file-protocol peer. They exercise admission, source retention, process
limits, pause/cancel/resume, checkpoint integrity, exports, editing and recovery.
Their synthetic bytes are not recordings or model weights.

A separate private integration check also launched the **unchanged supplied
corrected worker**, SHA-256
`21bcbe6c16f3b1d0cedec05469989e5b8256c5f2e3900f4b05f506c2c91df898`,
with a synthetic installed inference backend. The application consumed that
worker's actual checkpoint protocol, matched its actual reported installed-file
inventory, retained the input, and verified TXT/SRT/VTT/JSON outputs. This
establishes real compatibility with the supplied worker protocol. The private
worker source and private proof inputs are not included in the public repository.

**Real acoustic inference, model quality, native CPU/GPU compatibility, Windows
ASR execution, NVDA listening and distribution rights remain separate
qualification gates.** A trusted profile does not imply any of those results.
There is no inferred 135-language coverage, diarization, or word-level timing
claim. Whisper translation, when selected, targets English.

## Reuse decisions

The older public PR136 proposal was reviewed. Its bounded segment/text/timestamp
validation and millisecond formatting inform this adapter. Rounding first and
then dividing into hours/minutes/seconds correctly formats 59.9996 seconds as
`00:01:00,000`. The supplied worker's historical subtitle rollover is therefore
not copied into the workstation's exports.

PR136's in-process `WhisperModel`/`TranscriptionSession` path and its separate,
noncanonical audio job/model-manifest stack were not adopted. The current scope
requires the isolated supplied worker and durable application jobs. The existing
`durable_state` helpers, `audio.process.run_process`, shared `ResourceBroker`,
and no-clobber `research.export_file` publication are reused instead. PR135's
preparation-only language correction is superseded by the privately corrected
supplied worker; it is not an additional runtime.

## Register an existing installation

Select the exact local Python executable, reviewed Python worker file, and
existing model directory. Inspection only reads files; it never executes the
selected interpreter, worker or model code. It records:

- Interpreter launch path, resolved binary identity, and virtual-environment
  configuration. A final executable symlink is retained for ordinary virtual
  environments; the resolved target is pinned too. For a virtual environment,
  the operational `pyvenv.cfg` home also identifies the base executable: a
  copied Windows launcher alone cannot identify its base Python installation.
  The selected launch target and this operational base executable are pinned.
  Unused sibling executable aliases, such as a hosted `python3.exe`, are not
  execution inputs. A selected executable link's resolved target is checked
  again after inspection. The profile includes bounded adjacent Python/VC runtime
  DLLs, Python `_pth` configuration and Python ZIP archives when present, plus
  native `.pyd`/`.dll` files immediately inside the base installation's `DLLs`
  directory. Base site-packages lookup follows that same operational home when
  the virtual environment explicitly enables system packages.
- Worker source identity.
- The model's bounded ordered file inventory, including `model.bin`,
  `config.json`, and `tokenizer.json`.
- Content fingerprints of the seven installed ASR distributions: faster-whisper,
  CTranslate2, PyAV, ONNX Runtime, NumPy, huggingface-hub, and tokenizers. Installed
  file inventories and relevant Python path configuration are read from the
  explicitly selected environment without importing its code. Generated bytecode
  is excluded. Package version strings alone are insufficient.

This inventory covers the selected executable, the base and native support files
listed above, path configuration and the declared ASR distributions. It does not
attest every standard-library source file, every transitive dependency, OS
library, driver, or externally resolved import.

The owner must inspect and explicitly approve the returned fingerprint.
`register_runtime(..., owner_trusted=True, expected_fingerprint=...)` rechecks
the current bytes and rejects a stale inspection. Registration without trust is
permitted, but execution is disabled. The files are reverified at launch and
again after resource admission; changed runtime, dependency, worker or model
bytes require a new review. The worker's reported runtime/model identity must
also match the reviewed profile before a recognition checkpoint is accepted.

New checkpoint publication verifies the runtime/profile again immediately before
accepting a durable receipt and after a batch that accepted new results. Idle
polls and job listing do not rehash models. If verification observes a changed
runtime/model, new records accepted during that run are rejected; receipts
accepted before the run and all physical result files remain preserved. The
inactive worker workspace moves into the existing `worker-history` only after
the child process and its readers have closed. A durable `worker_cache_rejected`
flag is saved before that move; an interrupted/blocked archive must finish before
resume can inspect its cache. Restoring old model bytes cannot make that rejected
cache complete the job. This is point-in-time verification, not an immutable
model snapshot or detection of changes restored entirely between checks.

Cancellation reaches source, checkpoint and artifact hashes between bounded
read blocks and the bounded directory inventory. A stop observed during active
checkpoint verification enters the existing worker stop-flag/grace handling;
it does not wait for the complete multi-GiB source hash. Already committed valid
receipts remain available after an orderly stop. Storage calls themselves are
not interruptible OS operations, so immediate cancellation is not promised.

The child uses explicit `-I -B -X utf8`: isolation and UTF-8 are retained, while
`-B` prevents ordinary imports from writing or replacing generated bytecode in
the selected environment/base runtime. A parent's bytecode setting does not
substitute for this child argument. Runtime seals remain unchanged.

Models are reused **in place**. No download, package installation, weight copy,
paid call, online model fallback, or modification of the model directory occurs.
The supplied corrected worker requires ordinary local model files. A model
snapshot consisting of symlinks/reparse points cannot be passed to that worker
unchanged; it needs an explicit offline preparation of the already available
bytes into a regular local model directory. This adapter does not silently
materialize or redirect such a snapshot.

Trust authorizes execution of this owner-selected local code with the user's
normal account permissions. It is not an OS sandbox, publisher signature,
hardware attestation, license clearance, or guarantee against another process
maliciously replacing files during execution. Models and runtime packs remain
external to ordinary application-data backup and distribution.

## Jobs, progress and bounded control

The service receives files or folders; recursion is an explicit option.
Selection is bounded to 512 sources, 32 GiB per source and 64 GiB per job.
Original bytes are streamed into a private retained copy with before/after
identity checks, SHA-256 verification and atomic publication. Original paths
are provenance only; processing and recovery use retained bytes.

Execution uses an argument vector, `shell=False`, no inherited stdin and
isolated Python mode with explicit `-B -X utf8`. The command-line UTF-8 setting is
required because isolated mode ignores `PYTHONUTF8`; it preserves Unicode
protocol paths and Ukrainian diagnostics on Windows pipes. Protocol JSON reads
and writes explicitly use UTF-8. It sets offline flags and removes Python environment-path
injection variables. It does not provide a network sandbox around arbitrary
trusted local code. The existing subprocess runner bounds diagnostic output,
elapsed time, staging file count, output bytes and free-disk reserve. Its cleanup
completes before the resource reservation is released.

CPU slots, RAM and disk reservations are **cooperative scheduling estimates**.
They are not measured or OS-enforced process limits. The supplied worker passes
`num_workers=parallel_files` but does not expose an explicit native
`cpu_threads`/`inter_threads` control. Therefore this integration does not claim
that a reservation caps CTranslate2's actual thread count. CPU is the default.
CUDA needs explicitly configured broker capacity and the default, unmasked
device order for `cuda:0`; inherited GPU remapping is rejected rather than
silently reserving one device and using another. GPU memory and actual native
performance remain unqualified.

Settings are frozen for a job. Language remains the selected code or `auto`;
there is no implicit Russian/English substitution. Retries may use the supplied
worker's recorded decoding settings, and both requested and effective settings
remain in provenance.

Progress reports verified accepted source count separately from indeterminate
runtime/model verification and final process closure. A worker's progress string
does not establish completion. Pause requests a checkpoint stop and releases the
process/resources; resume starts a new worker for unfinished sources and reuses
accepted results. It does not promise continuation inside a native inference
segment. If a worker ignores cooperative stop, the bounded runner terminates it.
Pause intent takes priority over the UI's simultaneous cancellation event.

After an unclean parent-runner exit, the service marks the job interrupted and
requires confirmation that its external worker stopped before a retry. A stale
PID is not treated as safe process ownership, and the service does not kill an
unrelated process by PID. An orderly pause/cancel can be resumed directly.

## Acceptance, reading, edits and exports

The adapter accepts only atomic worker recognition checkpoints whose source,
settings, model inventory, runtime identity, text hash and structured metadata
hash match. It validates finite ordered timestamps, language, segment/text
agreement and size limits. It then creates its own immutable derived artifacts
and publishes their completion receipt last. TXT/SRT/VTT/JSON are produced from
the validated segments; a failed requested format cannot become success.

Accepted artifacts live outside the optional worker cache and are verified on
read and export. Partial failures retain previous accepted source results.
Edited reading copies are separate versioned derivatives; they do not alter
retained audio, the accepted original transcript, or quotation authority.
Runtime trust is not required to read, edit, back up or export existing results.

Exports use the application's atomic no-clobber writer and reject destinations
inside the entire private library. Existing user files are preserved. The export
manifest records checksums and source provenance. A temporary-file cleanup
warning after successful publication remains a saved result, with the warning
reported honestly. Recognition and edited text are labelled as derivatives;
neither becomes verified original quotation evidence.

## Backup and restore

The root is `<library>/state/transcription`. It contains `profiles/` and
`jobs/<id>/`, including retained `inputs/`, accepted `artifacts/`, `edits/` and
the durable job plan. Retained/artifact references are relative. Absolute worker
configuration is regenerated at launch. Optional worker caches can be omitted:
accepted results remain available, and retained originals permit recomputing
unfinished sources.

`prepare_restored_state(state_root, destination_root=None)` takes the complete
staged `state` directory. It executes nothing, revokes every external runtime's
trust, marks unfinished jobs for review, and removes transient worker flags,
status and absolute launch configuration. The user reviews a local installation
again. Rebinding a resumed job requires unchanged model content and worker
identity; a changed engine/model needs a new job. Completed results and edited
copies remain readable and exportable after restore without the external engine.
When an unfinished job is rebound to a changed profile, or rebound after restore,
the previous worker workspace is retained under that job's `worker-history/`
directory and a fresh workspace is used for unfinished sources. An unaccepted
recognition cache cannot acquire the new profile's provenance. Already accepted
artifacts keep their original receipts and runtime provenance. An unreviewed
interrupted worker must first be confirmed stopped before its workspace moves.
History directories are never execution or checkpoint-admission sources. Restore
also removes their old launch configuration, live settings, status and stop/pause
flags, while preserving inert historical results and accepted application data.

## Service API

```python
from carr_library.operations import ResourceBroker
from carr_library.transcription import TranscriptionService

service = TranscriptionService(
    library_root / 'state' / 'transcription',
    broker=ResourceBroker.for_app(library_root),
)
inspection = service.inspect_runtime(python, worker, model_directory)
# After the owner reviews that exact inspection:
profile = service.register_runtime(
    name, python, worker, model_directory,
    owner_trusted=True, expected_fingerprint=inspection['fingerprint'],
)
job = service.create_job(profile['id'], selected_paths, recursive=False,
                         settings={'language': 'auto', 'output_srt': True})
result = service.run(job['id'], progress=progress_callback, cancel=cancelled)
```

`inspect_runtime`, `register_runtime` and `create_job` accept optional `cancel`
and `progress` callbacks. `run`/`resume` are blocking operations for the existing
background-job controller; progress callbacks receive a dictionary. Controls
`pause`, `cancel`, and `continue_job` are small durable operations. Other methods
are `get_job`, `list_jobs` (`get`/`jobs` aliases), `read_transcript`, `save_edit`,
`export`, `rebind_runtime`, and `acknowledge_interruption(worker_stopped=True)`.
No service method accepts shell expressions, model download identifiers or
arbitrary remote endpoints.
