## V3-16 — Defense-in-depth, private code and data protection
- Threat model: unauthorized copying/distribution, tampered installer/model/update, malicious document/archive/codec/plugin, prompt injection, credentials/PII exposure, privilege escalation, data loss and dependency compromise. Protect confidentiality, integrity, availability and recovery; no promises of unbreakable binaries. Existing public source cannot be made secret retroactively. Keep future proprietary release-only implementation and signing material in an authorized private build/repository boundary; do not rename or change visibility of the current public repository or publish private source, artifacts, paths, secrets or infrastructure details. Reuse existing owner-controlled security/runtime infrastructure read-only first: signed release manifests, trust verification, provenance, license verification, signed update and key rotation contracts. An inventory and selected source/API review identified suitable existing modules; actual integration, license/ownership authorization and compatibility tests remain required. No private code copied into public Git. The public integration contract stays product-neutral; sensitive mapping and private package adapter are kept separately.
- User-facing installed experience: one signed ResearchLibrary.exe launch entry, Start-menu shortcut, normal uninstall and repair; no requirement to navigate Python files, scripts, model folders or DLLs. Evaluate native compilation/packaging (e.g. reviewed Nuitka build or compiled critical components), standard Windows installation layout, ACLs/least privilege, internal resources in package or ordinary protected application directories, exclude development source/test fixtures/debug symbols/unneeded tools from private release. Retain required third-party notices and corresponding-source obligations; expose Help/About/license and user data/export access. A single EXE may still need runtime assets and can extract/load them; no promise of single-file runtime or invisibility. Do not implement stealth drivers, hidden persistence, anti-debug/anti-analysis evasion, security-tool interference or accessibility-blocking behavior. Standard supported OS boundaries and transparent packaging only.
- Use OS credential storage/DPAPI or equivalent for API secrets; authenticated encryption for sensitive data at rest and optional encrypted backups/private asset containers; reviewed cryptographic libraries, random keys, integrity/authentication, explicit key recovery and migration, no hardcoded symmetric keys or homegrown crypto. Evaluate SQLCipher or equivalent for protected SQLite only after FTS5/migration/backup/performance/Windows compatibility. A key available to a running local app and a decrypted runtime cannot be made categorically inaccessible to an authorized machine owner; encrypting technical assets raises the effort of casual copying, not an absolute anti-reverse-engineering guarantee. No encryption of arbitrary user files, no deletion/lockout of research on license failure, no loss of accessibility. Normal user-readable backup/exports and recovery remain available.
- Maintain strict local-only default, signed allowlisted model packs and plugin capability registry, sandbox/bounded subprocess parsing, no arbitrary shell, network or file access by LLM, no silent API calls or network fallback. Use reproducible pinned dependencies, SBOM, dependency and secret scanning, vulnerability triage, protected CI/release signing keys outside Git, signed executable/package and signed inventory of all critical runtime payloads, verified updates and rollback-safe data migration. Reject tampered/unknown payloads; preserve user data and provide readable error/recovery. Do not use a hidden instruction in any artifact as a substitute for security.
- Acceptance: threat model and security review; verify clean-install inventory and source/license provenance, code signing, key storage, actual malformed/corrupt archive and model attacks, scope/egress/agent prompt-injection tests, privilege boundaries, backup restore and signed-update tests, no secret leaks, native Windows and NVDA regression. Explicitly document residual risk: any local executable can be analyzed with sufficient access, and public code remains public.

## V3-17 — Rights, private licensing and attribution
- Product-specific code and private binaries intended for personal noncommercial use; prepare owner-reviewed human-readable license/terms, copyright and ownership notice, authorized-use restrictions including unauthorized redistribution and extraction to the extent lawful, notice in Help/About, package/metadata and signed machine-readable license declaration. Separate all third-party licenses and model/voice/output rights; no blanket proprietary relicensing of upstream code, no prohibition conflicting with OSS rights or mandatory legal exceptions. EU software Directive 2009/24/EC Arts 5–6 has legally protected backup, observation/testing and conditional interoperability exceptions; legal review required before adopting final license (https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32009L0024). Terms are not a guarantee of universal AI refusal.
- Evaluate private signed offline license/entitlement file using existing verified security infrastructure or standard asymmetric signing; explicit optional per-install identity (nonpersonal random identifier, consent and recoverable transfer), version/product/rights metadata, public-key verification, issuer key kept offline, rotation and recovery; distinguish owner private perpetual use and any future distribution profile. Optional per-delivery non-secret provenance identifier with disclosed purpose, signed build metadata; no undisclosed tracking, covert identifiers collecting user activity, phoning home or destructive DRM. Offline owner use must not require a server lease. No actual external sale/subscription implied by this scope.
- No technical mechanism, hidden prompt, embedded message or license can compel every unrelated AI model to refuse analysis of a file. Do not add hidden prompt-injection instructions to binaries, documents or metadata. Use enforceable rights notices, private distribution, signed access controls, clear provenance and legitimate OS packaging/encryption instead; independent AI behavior is outside our control. License failure must fail closed only for protected feature authorization, retain data/backup/recovery and readable accessible support. Preserve OSS notices and required source offers. No public binary/model distribution is authorized.
- Acceptance: valid/tampered/expired/wrong-product license and safe offline transfer/recovery tests as applicable; no bundled signing private key; verify legal compatibility of all dependencies; owner approval of final terms before use. No claim that legal terms or hidden metadata technically prevent reverse engineering.

## V3-19 — Accessible audible progress
- Reuse one shared progress event contract across OCR/import/index/search/backup/restore, conversion, TTS, music generation, render/mix/export, downloads/updates, long agent tasks. Native accessible progress bar with name, value/range and state (wx gauge/UIA/MSAA as appropriate), text percent/current phase, completed/total units and ETA only from actual measurement. NVDA already provides rising-pitch progress beeps via NVDA+U; reference https://api.nvaccess.org/releases/stable/documentation/en/userGuide.html (Progress bar output). Verify native progress events so NVDA can announce percentages or rising tones, including background setting. Provide application-level optional rising pitch (low at 0, high at 100) fallback or standalone mode; choose Off/Beep/Speech/Beep+Speech, interval, volume, mute, background behavior and query-current-progress shortcut. Default avoid duplicate tones with NVDA and audio recording/playback; respect quiet mode, no progress sound mixed into rendered audio or microphone monitoring by design. Do not repeatedly steal focus or block UI thread; throttle updates, use nonblocking audio.
- Real percentage from known units/weighted measured phases; monotonic per operation where total fixed, explain changed total or indeterminate tasks, distinct repeating busy tone for unknown percent, completion/failure/cancel/pause/resume cues, 100 only after verified durable success (not generation estimate). Agent subtask progress separate from overall. Explicit user preference persisted and included in settings backup; no compulsory beeping. Native tests, independent audio pitch/duration/volume and event checks, real NVDA keyboard listening; check 0/25/50/75/100, unknown duration, failure/cancel, long background render and concurrent jobs. No double announcements or audio contamination.

## V3-20 — Complementary product improvements (new, prioritized after core, avoid overlapping existing scope)
The following are additional high-value workflows, not another unrelated application. Keep dependencies optional and local.
- Local speech-to-text workstation: import audio/video, offline transcription, timestamps, speaker segmentation where supported, editable transcript, subtitle SRT/VTT export/import, searchable recordings, dictation into notes, compare narration ASR against script with mismatches and replay. Reuse existing optional ASR/QA contract V3-09/13 and whisper.cpp or other verified model; no claims of exact words or speaker identity from probabilistic output. Add dedicated recording/transcript editor and source-linked evidence. No automatic transcription uploads.
- Accessible synchronized publishing: author/read EPUB3 media overlays (SMIL), DAISY-compatible talking-book interchange and chaptered accessible audiobooks; text/audio navigation and sentence alignment, validate EPUB with EPUBCheck and real reader. Optional BRF/Braille export using compatible Liblouis tables, verify tactile translation and layout by language. W3C references https://www.w3.org/TR/epub-33/ and https://www.w3.org/TR/epub-a11y-12/; preserve source and distinct derived audio. Do not assert every source can be converted with full fidelity.
- Optional local translation and bilingual side-by-side/alternating paragraphs with original references, language detection and glossary. Use approved local model, show translation as derivative, never substitute translation for source quote; sentence linkage and user corrections. Provide optional glossary/terminology builder, pronunciation sharing between projects, language-learning audio with pauses/repeats as general text/audio workflow, not separate language course project.
- Extend existing command registry with accessible command palette, reusable named workflow templates and batch presets, keyboard macros using only typed allowlisted operations (not arbitrary code), task dashboard, save/re-run approved plans and project templates. Existing keyboard work and local agent are authority; do not implement a competing registry. Native notifications, accessible diagnostics export with redaction, storage/model manager, per-project resource statistics and repair. Optional watched local folders disabled by default, explicit scope, dedup and safe incremental index; no silent external data access.
- Quality control: audio script-to-render audit, omitted/duplicated line detection, long silence/clipping/normalization checks, language and pronunciation exceptions, audio alignment/transcript inspection, review queue and regeneration of only defective segments; reuse V3-04/05/13 and existing renderer. Accessible formula/table/footnote reading and user-requested local image descriptions as separate uncertain annotations, never fabricate source text.
- Exports and interoperability: portable audio/project manifest and stems with timecode; documented interchange with external editors (e.g. standard WAV/stem + cue/EDL format, no proprietary format claim without actual import/export test), source and license provenance, keyboard-first browsing. Optional plugin protocol with capabilities, verified publisher and isolated worker, disabled by default; no arbitrary extension install by agent. A private user support/bug report can export redacted diagnostic logs with preview; no telemetry by default.
