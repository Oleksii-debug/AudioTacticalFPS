# Verified transcription receipt protocol

This adds a versioned adapter to the existing retained-input transcription
service. It contains no recognition engine, supplied private worker source,
model weights, installer, or model downloader.

The existing local-file-job/1 adapter remains available. A worker with an
adjacent protocol descriptor explicitly selects verified-file-job/1. A damaged
descriptor fails inspection; it cannot silently select the older decoder.

## Reviewed worker descriptor

The descriptor is the selected worker path with its suffix replaced by
.protocol.json. Its exact JSON fields are:

| Field | Required value |
| --- | --- |
| kind | whisper-transcribe-protocol |
| version | Integer 1 |
| protocol | verified-file-job/1 |
| worker | name, sha256 and size_bytes of the exact selected worker |
| helper | name, sha256 and size_bytes of recovery_support.py beside the worker |

No arbitrary companion path is accepted. The descriptor, worker and helper are
read as ordinary local files and independently hashed. Their bytes enter the
same profile fingerprint that the owner explicitly reviews. The descriptor is
a format declaration, not an authorization signature.

Removing, replacing or modifying a descriptor/helper invalidates an existing
profile. A changed worker or helper cannot be rebound into an existing job as
though it were the same implementation. A changed environment with unchanged
implementation follows the existing explicit rebind flow, which archives the
previous worker workspace and preserves accepted application receipts.

## Runtime identity

Inspection remains read-only. The application does not execute the selected
interpreter, import its packages, or run the worker during review.

The new adapter requires a normal local CPython virtual environment, Python
3.11 or newer, with system site-packages disabled and one unambiguous selected
site-packages directory. Embedded path overrides require a different reviewed
contract and are rejected here.

The inspector starts from faster-whisper, ctranslate2, av, numpy, onnxruntime,
tokenizers, huggingface-hub and packaging. It follows applicable Requires-Dist
metadata, including requested extras and environment markers, validates
installed version requirements and Requires-Python, and rejects missing or
ambiguous distributions. Requirement parsing uses the application's pinned
packaging 26.0 dependency. There is no automatic installation.

Every declared non-bytecode RECORD file is hashed, including native libraries,
metadata and model assets carried by a distribution. The canonical package
digest is SHA-256 over a sorted JSON list of path, sha256 and size_bytes records.
The protocol reports a sorted list of distribution name, version and digest.
The independently inspected list must match exactly: a seven-package subset
does not authorize a larger dependency closure.

Additional visible non-bytecode site-packages files are included in the profile
fingerprint, so adding an undeclared importable module also revokes review.
Sourceless bytecode is rejected. The selected interpreter, worker and helper are
separately hashed; the existing operational base-Python and native-support
inventory is retained. The operational base's ordinary standard-library source
and native files are also hashed, including the runpy/json/importlib bootstrap.
The optional CPython standard-library ZIP path and base libpython aliases are
pinned; missing or unsupported source-library layouts fail inspection.

Launch uses isolated Python, no automatic site processing, explicit UTF-8,
disabled bytecode writes, a fresh unwritten bytecode prefix and the exact
inspected site-packages path. This prevents cwd/user-site, .pth startup and
pre-existing generated bytecode from entering this launch path. Loader override
variables such as LD_PRELOAD and DYLD_LIBRARY_PATH are removed for this protocol.
It is not an
OS network sandbox. Offline environment flags remain in place, while actual
native network-denied engine qualification is a separate gate.

The worker's Python-version, platform and machine strings remain bounded
diagnostics. They cannot replace independently checked executable, companion
and package identities. This inventory does not attest every operating-system
library or GPU driver.

## Recognition and exported files

The adapter requests a separate TXT and structured JSON handoff for every
retained source. User-facing TXT/SRT/VTT/JSON exports continue to use the
existing application's publication service.

A recognition cache entry alone grants no admission. The decoder requires a
sealed per-file export receipt under logs/export-receipts, with a canonical
SHA-256 filename. It checks all of the following before the application
publishes its own durable result:

- The exact retained source path, parent and relative name, plus current source
  bytes, must match the application's input allowlist.
- The recognition request binds source bytes, the complete local model file
  tree, every recognition setting, the complete package inventory, and all three
  worker/helper/interpreter identities.
- The local model includes nonempty model.bin, config.json, tokenizer.json and
  vocabulary.txt. No name-based download fallback is available.
- Canonical request/result digests must match the content. Duplicate JSON keys,
  non-finite numbers, boolean integer substitutions and unknown schema fields
  are rejected.
- Segment/word times, text, explicit language and effective device/computation
  profile must pass the existing bounded result validation.
- Actual TXT and JSON export bytes must match the receipt. JSON source/request/
  result must equal the sealed recognition data, and TXT must equal its text.

All artifact paths are portable, relative and confined to the verified worker
results namespace. Symlinks, reparse points and hard-linked inputs are not
admitted. A transient create-only publication link grants no checkpoint
admission; final completion verification still requires ordinary single-link
files.

## Completion and recovery

The final completion.json is verified using the actual serialized file hash and
byte count referenced by job_status.json. It must have the same fresh run ID and
job name, exact selected source inventory, and the exact union of files sealed
by those sources' receipts. Duplicate inputs, duplicate/case-aliased output
paths, missing files and unrelated extra files fail completion. A completed
counter or a zero process exit is insufficient.

The service may expose individually accepted results from an interrupted or
partial run. The application reports complete only after every requested host
export has been verified and the applicable worker completion has been checked.
A failed final manifest write can be recovered by rerunning the existing
worker's cached handoff. A valid existing completion can be rechecked after a
host export failure without repeating recognition.

Pause keeps the existing stop-after-checkpoint and bounded process-cleanup
contract. Cancel also writes cancel.flag for this protocol. Resume and restore
remove that control flag; restore keeps external execution trust revoked.
Accepted application receipts remain outside the optional worker cache, retain
their original profile provenance and remain readable without executing a model.

## Evidence and integration boundary

The public fixtures are independently authored synthetic protocol peers. They
exercise real filesystem publication, subprocess launch, Unicode/isolated
runtime flags, cancellation, partial recovery and adversarially re-signed
receipts. They do not contain an acoustic recognizer and cannot establish
speech quality or supplied-worker compatibility by themselves.

Actual compatibility requires the separately repaired supplied worker, its
reviewed companion and descriptor, an exact locally installed dependency/model
pack, and an observed offline run through this service. Windows worker/native
accessibility and language/acoustic qualification remain explicit additional
evidence. No private source or model is published by the public test workflow.
