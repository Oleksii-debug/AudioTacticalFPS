# Optional converter qualification on Windows

This standalone gate prepares explicit test tools and runs synthetic local files.
It does not install, discover or download converters from the application, and it
does not grant a format a successful qualification before the gate actually runs.

At initial authoring, execution was **NOT_RUN** because the local executor was
unavailable. Actual frozen candidate `955165132fd530d6c3deb0e5b4b48f66dde77963`
subsequently passed all six selected-tool cases from source and all six from
the isolated installed wheel in run `45992503530`, job `140483608266`.
[The recorded evidence](evidence/optional-converter-observed-results-20261127.json)
retains that successful lane and the separate failed Office lane.

Later Office corrections remain subject to the complete seven-case source and
installed selection, including XLS. A source review, successful provisioning,
partial six-case run or a diagnostic census does not qualify all five Office
formats. No historical result is transferred to a changed source tree.

## Exact required populations

The workflow is .github/workflows/carr-converters.yml. Its independent matrix
jobs do not cancel each other when provisioning or one native filter fails.

| Job | Required source cases | Required isolated installed cases | Fixtures |
| --- | ---: | ---: | --- |
| selected | 6 | 6 | Synthetic RTF, external INCLUDETEXT field, bounded PNG/TIFF OCR, cancellation |
| office | 7 | 7 | Synthetic DOC/PPT/XLS generated by the selected office suite, minimal WPD and PalmDoc, cancellation, output limit |

Selectors are tests/conversion/test_selected_adapters_native.py and
tests/conversion/test_office_native.py. The acceptance helper checks each test
function's expected multiplicity, zero failure/error/skip, and rejects XFAIL/XPASS
through the existing ci_check child runner. An interrupted, missing or partial
report never becomes PASS. The XLS case remains required.

Both jobs build the candidate wheel, install the exact existing 18-pin Windows
runtime, and verify every installed carr_library/bootstrap Python file against
that source-bound wheel. Installed cases run under -I with pytest pythonpath
disabled. The evidence binds the exact Git commit/tree, helper/test hashes,
module origins, wheel hash and full selected runtime file inventory before and
after conversion. Each raw JUnit/log and all preparation diagnostics are uploaded
even when the gate fails.

No real user documents or proprietary fixtures are downloaded. These cases
qualify reading-copy behavior on these synthetic inputs, not printed pagination,
arbitrary document fidelity, language accuracy, a user corpus, or manual NVDA.

## Runtime pins and verification

packaging/conversion-runtimes.json is the fixed input lock for the gate.

* Pandoc 3.14 Windows x64 ZIP: official release URL, exact 43,614,099 bytes and
  SHA256 0144b96e8c7b023fd382ec5ef5bdc475e873f1019d6fa72502492df2c9a94a3b.
  The GitHub publisher release asset digest and size must match before the ZIP
  is downloaded; extraction rejects unsafe paths and bounds entries and bytes.
* LibreOffice 26.2.7 Windows x64 MSI: fixed official release URL and candidate
  SHA256 480fecf759fc6393bd614fbf43753eb95a8198fc1a065d41b727e3b664cd1e59.
  The initial authoring tool could not reach the deep MirrorBrain metadata.
  The actual gate therefore requires the publisher's exact HTTPS Metalink to
  independently match this digest and supply an exact size no larger than
  512 MiB before download or MSI administrative extraction. The recorded
  Windows Office runs passed this provisioning boundary; their later
  conversion failures remain failures. An unavailable or differing publisher
  response still fails the Office job. There is no fallback
  to a moving latest build, an unverified installer or a dropped XLS case.
* Tesseract 5.5.4: reuse the project's complete reviewed
  packaging/windows-ocr.lock.json and prepare_windows_ocr.py. This is an MSYS2
  UCRT64 package and closure, not an upstream Tesseract Windows installer.
  English tessdata_fast is fixed to revision
  87416418657359cb625c412a48b6e1d6d41c29bd and SHA256
  7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2.
  Existing manifest, source archive and orientation/model checks remain intact.

The fresh runner stages the verified tools under its temporary directory.
Administrative MSI extraction creates the selected test installation without
changing the application package. Outbound Windows firewall rules cover the
test Python and selected native executables before the first fixture conversion.
The application still uses its existing isolated owned worker, private profiles,
bounded outputs and complete process-family settlement.

A successful artifact is specific to that candidate and those runtime bytes.
Provider HTTPS metadata authenticates the published checksum; this gate does not
claim independently verified detached GPG signatures or reproducible vendor builds.
