# Пакетне перетворення явно вибраних аудіофайлів

Ця дія послідовно створює окремі оброблені копії через той самий
`AudioRuntime`, ресурсний брокер і видавець файлів, що й звичайне
**Convert audio and apply effects**. Вона не створює інший рушій, чергу,
планувальник чи сховище завдань. Темп і висота тону тут змінюють нову копію;
це не регулятори живого програвача.

## Вікно програми

1. Відкрийте **Audio Studio → Convert an explicit audio batch…**.
2. Явно виберіть від 1 до 64 локальних аудіо- чи відеофайлів.
3. У вже наявному редакторі задайте діапазон, частоту дискретизації,
   кількість каналів, бітову глибину/бітрейт та впорядковані типізовані ефекти.
   Іменовані пресети використовують той самий редактор ефектів.
4. Виберіть наявну зовнішню папку та один формат для всіх файлів.
   Окрема позначка **Explicitly resume saved audio batch** дозволяє повторно
   переглянути саме вже збережений пакет.
5. Програма перевірить байти кожного вибраного джерела та ідентичність
   фактично налаштованих FFmpeg/FFprobe на спільному робочому потоці.
   Цей перегляд не створює аудіофайлів чи маніфесту завершень.
6. Прочитайте список джерел, точні імена результатів, параметри та відбиток
   перегляду. Кнопка за замовчуванням **Keep audio review without running**
   залишає результати невиконаними. **Run exactly reviewed audio batch**
   запускає тільки переглянутий вибір.
7. **Cancel current operation** зупиняє роботу через чинний механізм
   скасування. Уже завершені файли та їхні квитанції зберігаються.

Імена мають явний порядковий номер: наприклад, `001-Розділ.wav` та
`002-Розділ.wav`. Номер усуває зіткнення однакових назв. Наявний файл
ніколи не перезаписується. Пакет зупиняється на першій помилці або
невизначеному результаті; наступні джерела не запускаються автоматично.

Список для перевірки є доступним лише для читання. Закриття вікна,
зміна об’єкта бібліотеки, її кореня або заміна каталогу за тим самим
шляхом скасовують повноваження відкладеної роботи й пізніх повідомлень.
Діалоги та робота використовують наявний host worker і ProgressHub.

## Командний рядок

Спочатку отримайте перегляд без кодування:

```powershell
python -B -m carr_library studio --data-dir C:\Library convert-batch `
  --input C:\Sources\First.wav --input C:\Sources\Second.wav `
  --output-dir D:\ReviewedAudio --format flac --channels 1
```

У JSON-відповіді буде `review_only: true` і `plan.id`. Для виконання
повторіть **ті самі аргументи** та додайте:

```text
--approve <точний plan.id>
```

Нова перевірка має дати той самий відбиток. Зміна джерел, їхнього порядку,
параметрів, налаштованих виконуваних файлів чи вихідного каталогу вимагає
нового перегляду. Саме збережений JSON не є дозволом на виконання.

Доступні також `--start`, `--duration`, `--sample-rate`, `--bit-depth`,
`--bitrate`, `--threads`, `--timeout`, `--max-bytes` та `--effects-json`.
Останній аргумент читає явно вибраний файл UTF-8 JSON до 64 KiB зі списком
не більш як 32 типізованих ефектів; довільний FFmpeg filtergraph не
приймається. Приклад:

```json
[
  {"kind": "gain", "parameters": {"gain_db": -6}, "enabled": true}
]
```

`--timeout` залишається чинним бюджетом **одного файлу**, а не заявою про
час усього пакета. `--max-bytes` обмежує суму завершених вихідних файлів;
кожне перетворення також виконує наявні консервативні перевірки джерела,
контейнера, тимчасових файлів, пам’яті, потоків і вільного диска.
Обмеження вибору: максимум 64 джерела, 8 GiB на джерело й 32 GiB сумарних
вхідних байтів, додатково до явно вибраного аудіобюджету.

Код завершення CLI: `0` — пакет завершено; `2` — частковий результат або
потрібна увага; `130` — скасування; `1` — відмова перегляду чи виконання.
JSON у перенаправленому Windows-потоці зберігає Unicode незалежно від
локальної кодової сторінки.

## Квитанції, продовження й невизначений результат

У вибраній зовнішній папці зберігається `conversion-manifest.json`
(максимум 4 MiB). Він містить явні шляхи джерел, їхні хеші, параметри,
ідентичність налаштованих локальних виконуваних файлів та окремі
квитанції фактичного результату. Він не містить ключів, моделей чи
дозволу довільно відкривати шляхи після відновлення.

Для продовження заново явно виберіть ті самі джерела, параметри й папку
та позначте Resume; у CLI додайте `--resume`, спочатку перегляньте нову
відповідь, потім повторіть команду з `--approve`. Програма повторно
перевірить завершені файли за **збереженими квитанціями фактичного
успішного повернення** чинного конвертера. Вони не кодуються повторно.

Намір публікації не є квитанцією завершення. Якщо процес загинув між
створенням аудіофайлу та записом успішної квитанції, або інша програма
встигла створити навіть байт-у-байт такий самий файл, результат має
статус **attention**. Пакет не:

- приймає збіг хешів за доказ того, що саме цей запуск створив файл;
- перезаписує, видаляє чи автоматично прибирає посилання/тимчасові файли;
- повторно кодує невизначений елемент у той самий або новий файл.

Потрібна явна перевірка користувачем. Після неї можна створити окремий
новий пакет у іншій папці лише для вибраних незавершених джерел.
У цьому вузькому сценарії немає автоматичної команди «прийняти наявний
файл як попередній успіх».

Якщо конвертер уже повернув успіх, але зберегти квитанцію не вдалося,
повідомлення прямо каже, що аудіофайл записано, а квитанція потребує
уваги. Пізня помилка повідомлення, скасування чи очищення не перетворює
факт запису на твердження «нічого не створено». Водночас наступний запуск
не вигадує втрачену квитанцію.

## Межі резервної копії та перенесення

Це зовнішній експорт. Звичайна повна резервна копія бібліотеки не
забирає довільну зовнішню папку, маніфест або вихідні аудіофайли.
Архівуйте їх окремо, якщо вони потрібні. Жоден новий тип стану бібліотеки
чи альтернативний формат резервних копій не додається.

Після відновлення або заміни кореня бібліотеки старий зовнішній пакет
не отримує автоматичних повноважень на продовження. Збережені шляхи
не відкриваються як інструкції: джерела й каталог завжди задає користувач
у новому перегляді. Перенесена папка також не вважається автоматично
тим самим переглянутим каталогом.

## Докази й межі перевірки

Додано окремі тести фактичного FFmpeg, явного CLI, контрольованих
діалогів, двох реальних аварійних меж дочірнього процесу, конкурентного
створення однакових байтів, часткового результату, жорстких посилань,
зміни бібліотеки/джерела/каталогу та відновлення бібліотеки.

Окремий Windows-пробник перевіряє встановлені модулі, реєстр команд,
реальні клавіші та діалоги з відмовою за замовчуванням, реальні PCM-файли
та продовження за квитанціями. Тільки результати файлових/каталогових
вибирачів задаються тестовими даними. Пробник не використовує мікрофон
або пристрій відтворення.

Наявність цих тестів не означає їх проходження. Новий склад джерел
потребує виконання портативних та встановлених Windows-перевірок.
Акустична оцінка, фізичні пристрої й ручна робота з NVDA залишаються
окремими видами доказів.
