# Інтеграція dordiai-voices: перевірений локальний контракт

Стан: 26 листопада 2026 року. Реалізовано тонкий адаптер CARR API 1 до
фактичного процесу `nvda_worker.py`. Приватне встановлення dordiai-voices
залишається окремим. У CARR не додано його вихідний код, каталог персональних
голосів, ваги моделей, записи або згенероване приватне мовлення.

## Перевірена основа

Прочитано `dordiai-voices/AGENTS.md`, `FINAL_PRODUCT_SPEC_UK.md`,
`selected_languages.json`, `WORK_STATE.json` та фактичні модулі
`source/0.12.2`. Гілка `unified-0.3.10` не використовується.

Фактичний `manifest.ini` має `name = kx47Voices`, `summary = dordiai-voices`,
`version = 0.13.1-dev.11`. Це назва і версія встановлення, а не приймання
готового синтезатора. `WORK_STATE.json` посилається на незмінну збірку
`84ca83e36e729fece88fc56af078a0de826d9db3`, але досліджена локальна копія не
має Git-метаданих. Її тотожність усьому тому коміту не заявляється.

У самого процесу немає RPC погодження версії або можливостей. Номер API 1

Це контроль сумісності конкретного процесу, не засвідчення всього приватного
пакета, залежностей інтерпретатора чи якості голосів.

## Фактичні інтерфейси встановленого проєкту

`models/voices/catalog.json` є плоским відображенням ідентифікатора голосу
на назву. Обгорток `voices` і `languages` у ньому немає. Кількість і склад
голосів CARR не фіксує. У власному короткому допоміжному процесі адаптер
викликає встановлені функції:

- `voice_policy.filter_voice_catalog(...)` застосовує чинні виключення.
- `voice_assets.discover_voices(references, engine_id="holos")` знаходить
  установлені керовані пакети та їхні сумісні ролі ресурсів.
- `language_catalog.coverage(models, selected_only=False)` повертає
  установлені, відсутні, часткові й експериментальні мовні можливості.
- `language_catalog.compatible_voice_ids(models, language, allowed_ids)`
  перевіряє структурну сумісність базових профілів. Для керованих пакетів
  додатково враховуються оголошена мова та необхідна роль активного ресурсу.
- `wide_languages.registered(code)` визначає справжній розширений маршрут.

Назва в каталозі без сумісних установлених ресурсів не потрапляє до
`voices()`. Ця перевірка не підтверджує вимову або акустичну якість.
Приватні модулі імпортуються тільки в окремому процесі, не в CARR.

Синтез запускає штатний приватний інтерпретатор з такими аргументами:

```text
python/python.exe -I -B -u nvda_worker.py models
  --reference-model models/Holos
  --references models/voices
  --reference-engine holos --preload-language mixed
```

Кожне повідомлення — один JSON-об'єкт із завершальним переносом рядка.
Кодування запиту ASCII із JSON-екрануванням Unicode; `stdout` містить відповіді,
а діагностика рушія не додається до тексту помилки користувача.

| Дія | Реальний запит / відповідь |
| --- | --- |
| Початок | `mode="reference"`, `profile`, явні `language`, `text`, `speed`, `stream=true`, `controls`; повертає `chunk` |
| Наступний блок | `{"mode":"next"}` → `chunk` або `{"finished":true}` |
| PCM | Base64, моно, signed 16-bit little-endian, 24 000 Гц |
| Завантаження | `loadingStage`: `language-source`, `selected-voice`, `voice-decoder`, `language-phonetics` |
| Скасування | `{"mode":"cancel"}` без підтверджувальної відповіді |
| Закриття потоку | `{"mode":"drop"}` → `{"finished":true}` |
| Помилка | `error` з назвою класу та `diagnostics`; CARR не показує приватні повідомлення/текст |
| Перевірка життєвого циклу | `{"mode":"preload","runtimeOnly":true}` → `ready` і `workerBootstrap` |

Після скасування адаптер спочатку дочитує відповідь на попередній запит,
потім чекає окреме підтвердження `drop`. Це не дозволяє старому `finished`
завершити новий фрагмент. Скасування, тайм-аут, порожній або некоректний PCM
завершуються помилкою; часткове озвучення не видається за успіх.

Перевірено нейтральну подачу та інтерфейси `speed`, `pitch`, `timbre`,
`volume`. SSML, явні фонеми, емоційні стилі, словник вимови як RPC та часові
мітки слів у цьому протоколі не встановлено; адаптер їх не рекламує.
Заміну вимови передавати вже підготовленим похідним текстом оповіді.
Оригінал джерела адаптер не редагує.

## Публічний API CARR

Реалізація: `carr_library.integrations.dordiai_voices`. Потрібна тільки
стандартна бібліотека Python. Штатний процес використовує власне зовнішнє
оточення dordiai-voices; CARR не встановлює його моделі чи Python-пакети.

```python
from threading import Event
from carr_library.integrations.dordiai_voices import DordiaiVoicesAdapter

stop = Event()
with DordiaiVoicesAdapter(runtime_directory) as engine:
    # runtime_directory: локальний каталог установленого add-on kx47Runtime.
    # Зазвичай він міститься в addons/kx47Voices/kx47Runtime.
    voices = engine.voices()
    capabilities = engine.capabilities()
    language_statuses = engine.language_statuses()
    selected_voice = voices[0]  # У продукті — збережений явний вибір користувача.
    language = selected_voice.languages[0]
    for block in engine.stream_pcm(
        narration_text, selected_voice.id, language,
        speed=1.0, pitch=50, timbre=50, volume=100,
        cancelled=stop,  # Також приймається callable () -> bool.
        progress=on_progress,
    ):
        pcm_sink.write(block.data)
```

`PCMChunk` має `data`, `sample_rate`, `channels`, `sample_width`, `frames`.
`DordiaiProgress` має `stage`, `rendered_frames`, `rendered_seconds`.
Кількість уже створених семплів не називається відсотком завершення або
часовими мітками слів. Перед вибором індексу голосу викликальна сторона
обробляє порожній каталог і показує відсутні ресурси.

`cancel()` сигналізує активне завдання; `close()` звільняє процес і потоки.
Один екземпляр виконує один потік озвучення одночасно і зберігає прогрітий
процес між послідовними фрагментами. Паралельний запит повертає
`DordiaiBusy`. Події скасування допускаються з іншого потоку.

Робочий процес слід викликати у фоновому працівнику читача/студії. Поточний
спільний виробничий код CARR володіє WAV-файлом, плеєром, атомарним
збереженням, чергою багатогодинного проєкту й кешем; адаптер повертає PCM
та не дублює цей функціонал. Фасад спільного реєстру може додавати префікс
`dordiai-voices:` до ідентифікатора голосу й знімати його перед викликом.
До ідентичності кешу включають API адаптера, відбиток процесу, версію/маніфест
установлення, голос, мову, текст і всі акустичні параметри.

Для пакування додати `carr_library.integrations` до явного списку
`tool.setuptools.packages`, якщо інтегратор ще цього не зробив. Обидва файли
`dordiai_voices.py` та `_dordiai_probe.py` мають бути в пакеті.

## Межі процесу та конфігурації

Використовуються лише вибрані локальні шляхи, абсолютні аргументи й
`shell=False`; HTTP-службу не створено. Вбудований інтерпретатор має бути
встановлений. Необов'язковий `python_executable` підтримує окремо
підготовлене локальне оточення та діагностику. Зміна відбитка процесу не
відбувається автоматично. Шляхи до стандартних файлів не можуть виходити
за вибраний каталог runtime після розв'язання посилань.

Черги та кадри обмежені: два вихідні повідомлення, вісім вхідних, до 1 МіБ
на запит і 16 МіБ на відповідь. Один фрагмент тексту має максимум 16 384
символи, один потік цього фрагмента — максимум чотири години PCM. Довший
проєкт виробничий планувальник ділить на відновлювані фрагменти. Нерухомий
читач stdin не блокує основний потік: окремий писач і дедлайн відповіді
дозволяють завершити власний завислий процес.

Встановлюються стандартні offline/telemetry-off змінні для локальних
модельних бібліотек. Вони не є ізоляцією стороннього нативного коду або
системним міжмережевим екраном. Інтерпретатор і зовнішнє встановлення є
довіреним локальним програмним забезпеченням. Не можна безумовно забороняти
всі дочірні процеси: справжній штатний російський маршрут використовує
окремий локальний виконавчий файл. Якщо продукт потребує OS-ізоляції,
дозволи мають описувати перевірені штатні залежності.

## Перевірки і відкриті приймальні вимоги

Звичайний незалежний набір контрактних тестів не потребує приватного
рушія та не містить пропусків:

```text
python -m pytest -q tests/integrations/test_dordiai_voices.py
```

Він використовує тільки вигадані ідентифікатори й короткий синтетичний PCM,
перевіряє дійсну послідовність повідомлень, відповідність мовних маршрутів,
скасування/дочитування, повторне використання процесу, відсутні ресурси,
обмеження буферів, зміну пакетів і невдалий/завислий процес. Такі тести не
підтверджують акустичний синтез.

Окремий файл `dordiai_private_probe.py` навмисне не збирається типовим
pytest-gate. Його викликають явно з `CARR_TEST_DORDIAI_RUNTIME`, що вказує
на вже наявний приватний `kx47Runtime`:

```text
python -m pytest -q tests/integrations/dordiai_private_probe.py
```

На доступному Linux-вузлі виконано обидва справжні upstream-випробування:
реальні функції інвентаризації, `preload`, структурована помилка через
відсутню конфігурацію голосових ресурсів, `cancel`, `drop`, чистий вихід 0.
Досліджена копія повернула 173 записи інвентаризації й нуль готових
поєднань голос/мова. Це фактична відсутність потрібних ресурсів у цій копії,
а не підстава оголошувати голоси доступними. Файли приватного проєкту
під час перевірки не копіювалися та не змінювалися.

Залишаються окремими обов'язковими перевірками: справжній синтез на
повному вибраному Windows-встановленні, звуковий вихід, вимова,
вимірювання затримок, життєвий цикл нативних дочірніх рушіїв після
примусового завершення та доступність остаточного CARR у Windows/NVDA.
Успіх протокольного з'єднання не закриває ці перевірки.
