# Пакетний переклад кількох документів

Цей процес об’єднує вже наявні завдання перекладу в один перевірений порядок.
Кожен документ має окреме підтвердження дозволу, власні збережені частини та
незалежні квитанції обліку запитів. Виконавець, облікові записи й механізм
передавання тексту залишаються спільними з одиночним перекладом.

Локальний профіль `libretranslate-local` працює в тому самому процесі
перегляду й пакетної обробки. Для нього вкажіть нульовий резерв і явно
підтвердьте локальне передавання. Для пакета з локальними й зовнішніми
профілями підтверджуються обидва види передавання.
[Налаштування й перевірки локального перекладу](LOCAL_TRANSLATION_UK.md).

## Що підтримується

У меню **Tools → Translate reviewed document batch...** можна додати явно
вибрані файли UTF-8 або кілька книг поточної бібліотеки. Для кожного рядка
зберігаються обліковий запис, мови, необов’язковий глосарій Advanced v3 та
зазначений користувачем резерв коштів. Команда **Apply settings to selected
document** змінює лише вибраний рядок; **Move up/down** змінює порядок.

В інтерфейсі вибирається весь збережений текст книги. CLI також приймає явний
діапазон позицій читання або одну главу EPUB. Сторінки PDF, розділи та позиції
читання не прирівнюються одне до одного без даних джерела.

Межі одного пакета: 32 документи та 2 000 000 вихідних символів. Число
перевірених перекладених символів для спільного ZIP також обмежене 2 000 000;
окремі завершені квитанції не зникають, якщо загальний пакет перевищив цю межу.
ZIP і сукупність підготовлених файлів обмежені 64 MiB. Зберігається щонайбільше
256 пакетів.

Результат — **окремі текстові похідні**. Верстка DOCX/PDF/EPUB, таблиці,
зображення й стилі не відтворюються. Вихідні книги та їхні права цитування не
змінюються; переклад не стає перевіреною цитатою оригіналу.

## Перегляд, дозвіл і запуск

1. Виберіть активну бібліотеку та за потреби тему. Додайте конкретні файли або
   книги, перевірте облікові записи, мови, глосарії й порядок.
2. Натисніть **Review entire translation batch**. Перегляд показує точні
   джерела, облікові записи/кінцеві адреси, кількість символів та запитів,
   резерви кожного документа і загальну суму. Текст ще не передається.
3. **Prepare approved batch** запитує окрему згоду для цього точного перегляду.
   Зміна тексту, порядку або налаштувань потребує нового перегляду. Підготовка
   зберігає звичайні завдання перекладу, але не надсилає текст провайдеру.
4. **Run or resume batch** запускає їх послідовно на наявній черзі. Кожна
   прийнята частина записується до переходу до наступного запиту.
5. **Pause batch**, закриття власного вікна або Ctrl+C у CLI зупиняють подальшу
   роботу. Підтверджені результати залишаються. Невизначене списання коштів
   потребує звірки обліку: автоматичного повторного платного запиту немає.

Обліковий запис повторно перевіряється перед передаванням. Для збережених
бібліотечних джерел повторно перевіряються поточна область доступу, точний
оригінал, ревізія, вибрані позиції та метадані. Пакет не може використати
змінену книгу під старим дозволом.

Сума резерву є межею локального дозволу на запити, а не гарантією тарифу чи
зовнішнього рахунку провайдера. За відсутності явної договірної ставки оцінка
ціни не вигадується.

## Відновлення та експорт

Відкриття збереженого пакета, перегляд стану, резервне копіювання і відновлення
не виконують мережевих запитів. Незавершену підготовку можна продовжити
командою **Prepare** без повторного створення вже наявних дочірніх завдань.

Повна резервна копія common4 зберігає незмінний опис пакета, звичайні завдання
перекладу та їхні наявні квитанції. Після відновлення керувальний стан пакета
стає **pause**. Старі дозволи не подовжуються, а їхні вихідні байти не
переписуються. Бібліотечні завдання, перенесені до іншої ідентичності каталогу,
потребують нового перегляду й дозволу перед подальшими зовнішніми запитами.
Завершені квитанції залишаються доступними для локальної перевірки та експорту.

**Export completed ZIP** працює лише тоді, коли всі документи перевірено
завершені. Потрібно вибрати новий шлях: заміна наявного ZIP не дозволена.
Кожен підкаталог містить:

- original.txt;
- translated.txt;
- bilingual.txt;
- translation.reading.json;
- translation-provenance.json.

Загальний batch-provenance.json містить ідентичності дочірніх завдань,
ідентичність перегляду та SHA-256 кожного файла. Квитанції перевіряються за
незалежним збереженим обліком запитів; самостійно перерахований хеш зміненого
тексту не підтверджує переклад.

## CLI

Для CLI потрібна наявна приватна бібліотека з налаштованим обліковим записом
перекладу та явно отриманим переліком підтримуваних мов. Приклад опису:

~~~json
{
  "schema": "carr-translation-batch-input/1",
  "title": "Два явно вибрані документи",
  "items": [
    {
      "profile": "my_translation_account",
      "input": "first.txt",
      "source": "en",
      "target": "uk",
      "budget": "1"
    },
    {
      "profile": "my_translation_account",
      "workspace": "EXACT_WORKSPACE_ID",
      "edition": "EXACT_EDITION_ID",
      "first": 1,
      "last": 2,
      "source": "en",
      "target": "uk",
      "budget": "1"
    }
  ]
}
~~~

Шляхи input, записані без кореня, відлічуються від каталогу цього JSON.
Файли не шукаються автоматично. Один рядок вибирає файл або бібліотечне
джерело; ці режими не змішуються. Для глави EPUB використовується chapter
замість first/last. Текст і байти підтвердженого джерела фіксуються під час
перегляду й підготовки.

~~~text
python -B -m carr_library translate-batch --data-dir LIBRARY preview --batch-file batch.json
python -B -m carr_library translate-batch --data-dir LIBRARY submit --batch-file batch.json --approve-remote --review-sha256 EXACT_REVIEW_SHA256
python -B -m carr_library translate-batch --data-dir LIBRARY review BATCH_ID
python -B -m carr_library translate-batch --data-dir LIBRARY prepare BATCH_ID
python -B -m carr_library translate-batch --data-dir LIBRARY resume BATCH_ID
python -B -m carr_library translate-batch --data-dir LIBRARY pause BATCH_ID
python -B -m carr_library translate-batch --data-dir LIBRARY export BATCH_ID --output NEW_PACKAGE.zip
~~~

Завершене виконання повертає код 0, явна пауза виконання — 2, помилка — 1.
Команда pause лише зберігає запит паузи; вона не запускає виконавець.
Для локального пакета замість `--approve-remote` використовується
`--approve-local`. Змішаний пакет вимагає обох прапорців; резерв кожного
локального рядка дорівнює нулю.

## Межі підтвердження

Синтетичні перевірки використовують справжні локальні завдання, облік запитів,
резервні копії та ZIP, але керовану відповідь HTTPS. Native Windows probe
перевіряє фактичний Desktop, вибір кількох книг, перегляд, підготовку, паузу,
продовження, експорт і видалення власного вікна під час роботи. Його відповіді
на системний діалог дозволу й файловий picker є контрольованими даними тесту;
фізичний ввід, NVDA, платний Google API та мовна якість цим не підтверджуються.

Нові вихідні тексти мають пройти точні source/installed/native gates. Сам факт
наявності probe або статичного схвалення не є результатом його виконання.
