# Локальний переклад вибраного тексту

Resonance може передати явно вибраний текст до вже налаштованого локального
сервера з протоколом LibreTranslate. Використовуються ті самі вікна, завдання,
квитанції та пакетний експорт, що й для Google Basic v2 та Advanced v3.

## Налаштування

У вікні AI/API connections виберіть адаптер `libretranslate-local`.
Вкажіть адресу на зразок `http://127.0.0.1:5000`, назву профілю та опис
моделей сервера. Увімкніть профіль і явно виберіть його у вікні перекладу.

Адреса має містити числову loopback-адресу цього комп’ютера. Доступні HTTP та
HTTPS; для HTTPS застосовується звичайна перевірка сертифіката й імені/IP.
Шляхи API, параметри запиту, облікові дані в URL, назва `localhost` та
адреси інших комп’ютерів не приймаються. Програма не використовує системні
HTTP proxy-змінні для цього адаптера. DNS-запит не потрібен.

Ключ API, OAuth-токен, голос, модель генерації чату чи глосарій не передаються.
Профіль дозволяє лише запит списку мов і переклад вибраного тексту.
Resonance не встановлює й не запускає сервер, не завантажує його моделі
та не підтверджує, які саме моделі сервер фактично використовує.

Сумісність клієнта визначена за маршрутами `GET /languages` і
`POST /translate` LibreTranslate v1.10.0, вихідний код
[зафіксованої версії](https://github.com/LibreTranslate/LibreTranslate/blob/29aea44cc80100401497fb62db813a3f3a504e84/libretranslate/app.py).
Сервер має працювати без ключа API на явно вибраній loopback-адресі.

## Перегляд і виконання

1. У вікні перекладу виберіть локальний профіль.
2. **Fetch languages** окремо запитує дозвіл отримати заявлені сервером
   напрямки перекладу. Текст документа цим запитом не надсилається.
3. Виберіть вихідну й цільову мови. `auto` дозволено лише для вихідної мови.
   Заявлена сервером пара має дозволяти саме вибраний напрямок.
4. Для резерву коштів введіть **0**. Локальний адаптер не резервує зовнішню
   плату. Не задавайте глосарій чи ненульову ставку за символи.
5. Натисніть **Preview**, перевірте текст, адресу, мови та кількість запитів.
6. **Translate / resume** просить дозвіл на точний переглянутий текст.
   Зміна джерела або налаштувань потребує нового перегляду.

Кожен запит зв’язаний із точним вмістом, адресою, профілем і своїм дозволом.
Дозвіл на локальний переклад не дозволяє виклик зовнішнього провайдера.
Профіль повторно перевіряється перед надсиланням і прийняттям відповіді.
Для бібліотечного джерела додатково перевіряються поточна область доступу,
оригінальні байти, ревізія, вибрані позиції та метадані.

Програма приймає звичайний текст. Переклад не відтворює верстку PDF, DOCX
або EPUB. Символи на зразок `&amp;` залишаються точним текстом відповіді,
без неузгодженого HTML-перетворення.

## Пауза, невизначений запит і відновлення

Пауза або закриття власного вікна припиняють наступні запити. Для локального
HTTP/TLS скасування також перериває очікування мережевої відповіді.
З’єднання і службовий потік закриваються до завершення операції.

Прийнята частина записується разом із незалежною квитанцією обліку.
Після невизначеного завершення запиту програма не повторює його автоматично
і не переходить на інший сервіс. Це правило діє й за нульового резерву коштів.

Резервна копія зберігає завдання, заявлені мовні пари, дозволи та квитанції,
але не запускає переклад. Після відновлення бібліотеки в іншому каталозі
незавершене завдання, прив’язане до джерела, потребує нового перегляду й
дозволу для відновленої бібліотеки. Старий дозвіл не переприв’язується.

Повністю завершений результат можна перевірити й експортувати офлайн,
навіть після видалення профілю або завершення строку дозволу.
Перевірка точного джерела та квитанцій результату залишається обов’язковою.

## Кілька документів

У **Tools → Translate reviewed document batch...** доступні локальні та
зовнішні профілі. Перегляд показує адресу й резерв кожного документа.
Локальні рядки мають нульовий резерв. Для змішаного пакета явно
підтверджуються обидва види передавання.

Пакет використовує вже наявні завдання кожного документа. Підготовка не
надсилає текст; **Run or resume batch** виконує підтверджені рядки.
Готовий пакет експортується в новий ZIP. Докладні кроки й межі наведені в
[інструкції пакетного перекладу](TRANSLATION_BATCH_UK.md).

## CLI

Команди використовують уже створену бібліотеку та збережений локальний профіль:

~~~text
python -B -m carr_library translate --data-dir LIBRARY languages --profile LOCAL_PROFILE --approve-local
python -B -m carr_library translate --data-dir LIBRARY preview --profile LOCAL_PROFILE --input selected.txt --source en --target uk --budget 0
python -B -m carr_library translate --data-dir LIBRARY submit --profile LOCAL_PROFILE --input selected.txt --source en --target uk --budget 0 --review-sha256 EXACT_REVIEW_SHA256 --approve-local
python -B -m carr_library translate --data-dir LIBRARY resume JOB_ID
python -B -m carr_library translate --data-dir LIBRARY export JOB_ID --output NEW_DIRECTORY
~~~

Без `--approve-local` команда `languages` лише читає збережений список.
Прапорець `--approve-remote` не дозволяє локальний запит.

Для локального пакета використовуйте `translate-batch submit` з
`--approve-local` і точним `--review-sha256`. Змішаний пакет вимагає
обох прапорців: `--approve-local --approve-remote`.
Наступні `resume` використовують саме збережені дозволи.

## Що означає результат

Експорт містить оригінал, переклад, двомовний текст, копію для читання та
походження результату з контрольними сумами. Переклад залишається похідним
текстом і не набуває права цитування як перевірений оригінал.

Перевірки протоколу охоплюють фактичні loopback HTTP/TLS-з’єднання,
скасування, точні запити, квитанції, CLI, резервне копіювання та вікна.
Вони не вимірюють мовну якість реального сервера й не доводять, що сам сервер
ніколи не звертається до мережі. Ідентичність серверних моделей, якість
перекладу й його власні мережеві дії оцінюються окремо. Точний статус
виконання кожної перевірки визначається звітом для конкретного коміту.
